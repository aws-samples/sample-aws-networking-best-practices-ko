# コネクティビティ {#connectivity}

このセクションでは、AWS リソースがインターネット、相互間、および AWS 外部のネットワークとどのように通信するかを説明します。コネクティビティは、基盤となるインフラストラクチャ(VPC、サブネット、IP アドレッシング)と、その上で動作するアプリケーションネットワーキングサービスの間に位置するレイヤーです。

選択するコネクティビティパターンは、AWS 環境全体のコスト、レイテンシー、セキュリティ境界、および運用上のオーナーシップに影響を与えます。多くの組織では複数のコネクティビティサービスを同時に使用しており、それぞれが最も価値を発揮するレイヤーで機能しています。

**各ページの関係:** インターネットコネクティビティは外部境界(トラフィックが AWS に出入りする方法)を扱います。AWS 内コネクティビティは、VPC とアカウント間の内部ルーティングとサービス通信を扱います。ハイブリッド & マルチクラウドは、AWS 外部のネットワーク(オンプレミスのデータセンターや他のクラウドプロバイダー)への接続を扱います。リモートアクセスは、認可されたユーザーとデバイスが内部アプリケーションにアクセスする方法を扱います。多くのアーキテクチャはこの 4 つすべてに関わります。公開ワークロード向けのインターネット、それらを結ぶバックボーンとしての AWS 内コネクティビティ、オンプレミスおよびマルチクラウド区間のハイブリッド、そして従業員向けのリモートアクセスです。

!!! tip "VPC Lattice について"
    Amazon VPC Lattice は設計上、2 か所に登場します。[AWS 内コネクティビティ](within-aws.md)ページでは、コネクティビティおよびネットワークチームの視点から VPC Lattice を説明します。具体的には、サービスネットワーク、アソシエーションモデル、およびコネクティビティスタックにおける VPC Lattice の位置づけです。[アプリケーションネットワーキング → サービス間通信](../application-networking/service-to-service.md)ページでは、アプリケーションチームの視点から VPC Lattice を説明します。具体的には、サービスディスカバリー、認証ポリシー、トラフィック管理、およびデプロイパターンです。

## 1. インターネットコネクティビティ {#1-internet-connectivity}

**インターネットコネクティビティ**は、**イングレス**(外部クライアントが AWS でホストされたアプリケーションにアクセスする方法)と**エグレス**(AWS リソースがインターネット上の外部サービスにアクセスする方法)という 2 つの異なる関心事を扱います。それぞれに適したパターンは異なる基準に依存しており、一方の決定がもう一方にそのまま適用できることはほとんどありません。

**主な決定事項:**

*   **イングレス: 分散型 vs 集中型** — 分散型(各 VPC が独自のイングレスを管理)が推奨されるデフォルトです。集中型(共有イングレス VPC)は特定のコンプライアンス要件がある場合に限定されます
*   **エグレス: IPv6 vs IPv4** — IPv6 エグレスは設計上分散型です(VPC ごとのエグレス専用インターネットゲートウェイ)。IPv4 エグレスは分散型と集中型の間で真のトレードオフが存在します
*   **エッジサービス** — Amazon CloudFront、AWS Global Accelerator、および AWS WAF は、イングレスパターンに関わらず一元管理された保護を提供します

***重要なインサイト:*** *イングレスについては、AWS エッジ(CloudFront、AWS WAF、VPC ごとのファイアウォールエンドポイント)が事実上、一元管理されたグローバル分散型の境界となります。これにより、すべてのフローを共有リージョンイングレス VPC 経由でルーティングしていた従来の理由がなくなります。*

## 2. AWS 内コネクティビティ {#2-connectivity-within-aws}

**AWS 内コネクティビティ**は、VPC、アカウント、およびリージョン間の通信を処理します。サービスは 2 つの補完的なレイヤーで動作します。ネットワークレベルのコネクティビティ(VPC がトラフィックをルーティングする方法)と、アプリケーションレベルのコネクティビティ(サービスが相互を検出して通信する方法)です。

**主なサービス:**

*   **AWS Cloud WAN** — 宣言的なセグメンテーションを備えたポリシー駆動型のグローバルネットワーク管理
*   **Amazon VPC Lattice** — IAM ベースの認証を備えたアプリケーションレイヤーのサービス間通信
*   **VPC Lattice VPC Resources** — データベース、オンプレミスエンドポイント、およびサードパーティサービスへのプライベート TCP アクセス
*   **AWS Transit Gateway** — VPC、VPN、および Direct Connect のためのリージョンハブアンドスポークルーティング
*   **AWS PrivateLink** — AWS サービスへのプライベートアクセスと、自社サービスを他のアカウントに公開する機能
*   **VPC Peering** — 特定の正当化された VPC ペア間の直接ポイントツーポイント接続

***重要なインサイト:*** *これらのサービスは競合する代替手段ではなく、補完的なレイヤーです。各サービスが最も価値を発揮するレイヤーで機能するコネクティビティスタックを構築してください。*

## 3. ハイブリッド & マルチクラウドコネクティビティ {#3-hybrid-and-multi-cloud-connectivity}

**ハイブリッド & マルチクラウドコネクティビティ**は、2 つの異なる関心事を扱います。オンプレミスのデータセンターやブランチオフィスを AWS に接続すること(ハイブリッド)と、AWS を他のパブリッククラウドに接続すること(マルチクラウド)です。

**主なサービス:**

*   **AWS Direct Connect** — 予測可能な帯域幅とレイテンシーのためのプライベート専用回線。ほとんどの本番ハイブリッドデプロイメントの基盤
*   **AWS Site-to-Site VPN** — インターネット経由の暗号化された IPsec 接続。ハイブリッド接続を確立する最速の方法
*   **SD-WAN 統合** — 既存の SD-WAN オーバーレイのための Transit Gateway Connect または AWS Cloud WAN Connect アタッチメント
*   **AWS Interconnect** — マネージドなクラウド間直接接続(現在は AWS ↔ Google Cloud、拡張予定)

***重要なインサイト:*** *多くの組織はこれらのサービスを複数同時に使用しています。プライマリプライベートパスには Direct Connect、高速スタートまたは暗号化オーバーレイには VPN、既存のブランチオーバーレイには SD-WAN Connect を使用します。*

## 4. リモートアクセス {#4-remote-access}

**リモートアクセス**は、認可されたユーザーとデバイスが内部 AWS アプリケーションにアクセスする方法を扱います。これはインフラストラクチャコネクティビティとは異なる決定領域です。ネットワークエンジニアリングではなく、アイデンティティおよびセキュリティチームに向けたものであり、環境にハイブリッド接続があるかどうかに関わらず独立して機能します。

**主なサービス:**

*   **AWS Verified Access** — リクエストごとのアイデンティティとデバイスポスチャー評価を備えたゼロトラストアプリケーションレベルアクセス。新しいユースケースに推奨されるオプション
*   **AWS Client VPN** — VPC 内でルーティング可能な IP アドレスが真に必要なケース向けの、ネットワークレベルのユーザーアクセス

***重要なインサイト:*** *新しいアプリケーションアクセスのユースケースにはすべて AWS Verified Access から始めてください。Client VPN は、アプリケーションがユーザーに VPC 内のルーティング可能な IP を真に必要とする場合にのみ使用してください。*
