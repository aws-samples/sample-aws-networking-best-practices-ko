# 修正を報告する {#report-a-correction}

この AWS ネットワーキングアーキテクチャガイダンスは複数のページで構成されており、機能・設定などに関する詳細な情報を含んでいます。不整合を発見した場合や改善の余地があると感じた場合は、このガイドに従って [issue tracker] に Issue を登録してください。

  [issue tracker]: https://github.com/aws/aws-networking-best-practices/issues

## Issue テンプレート {#issue-template}

Issue を作成する前に、このガイドをよくお読みください。[新しいドキュメント修正 Issue](https://github.com/aws/aws-networking-best-practices/issues/new?template=correction.md) を作成する際は、以下の情報を含めてください。

* タイトル
* 説明
* 関連リンク
* 提案する変更（任意）

### タイトル {#title}

良いタイトルとは、Issue を簡潔に一文で表したものです。関連するすべての情報、特に Issue トラッカーでの検索を容易にするキーワードを含めてください。

| <!-- --> | 例  |
| -------- | -------- |
| :material-check:{ style="color: #4DB6AC" } **明確** | マルチクラウドシナリオにおける DX の使用方法を明確化する |
| :material-close:{ style="color: #EF5350" } **不明確** | ドキュメントに情報が不足している |
| :material-close:{ style="color: #EF5350" } **不適切** | 助けてください |

### 説明 {#description}

ドキュメントで見つけた不整合や問題、または改善が必要なドキュメントのセクションについて、明確かつ簡潔にまとめてください。ドキュメントを修正すべきと考える理由と、問題の深刻度を説明してください。

*   **簡潔にまとめる** – 不整合や問題を 1〜2 文で正確に説明できる場合は、それで十分です。メンテナーや将来のユーザーが読む量を減らせることに感謝されるでしょう。

*   **1 つの Issue につき 1 件の問題** – 無関係な不整合が複数ある場合は、それぞれ別の Issue を作成してください。同じ Issue にまとめて報告すると、原因の特定が困難になります。

> **この情報が必要な理由**: 問題を明確かつ簡潔に説明することは、ドキュメントを改善するための前提条件です。何が問題なのかを理解して初めて、修正が可能になります。

### 関連リンク {#related-links}

上記で修正が必要なドキュメントのセクションを説明したら、そのセクションおよび関連する可能性のある他のセクションへのリンクを共有してください。可能な限りアンカーリンク（パーマリンク）を使用すると、発見が容易になります。

> **この情報が必要な理由**: ドキュメントへのリンクを提供することで、どのセクションを修正・拡充・見直す必要があるかを把握しやすくなります。

### 提案する変更 <small>任意</small> { #proposed-change }

説明と関連するドキュメントセクションへのリンクを提供したら、改善案を提案することでメンテナーやコミュニティに貢献できます。大まかなアイデアのスケッチでも、具体的な提案でも構いません。このフィールドは任意ですが、非常に参考になります。

> **この情報が必要な理由**: 改善提案は、同じ問題に直面した他のユーザーにとって有益です。メンテナーがドキュメントを更新する前に、解決策を提示できるからです。

**あとはこちらで対応します。**
