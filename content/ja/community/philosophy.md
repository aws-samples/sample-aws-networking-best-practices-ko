# 哲学 {#philosophy}

プロジェクトの哲学を理解することで、効果的な貢献が可能になり、目標との認識を合わせることができます。このページでは、AWS Networking Best Practices ガイドのコンテンツ作成、レビューの判断、および全体的な方向性を導くコア原則を説明します。

## なぜ重要なのか {#why-this-matters}

アーキテクチャの意思決定にこのガイドを活用する場合でも、新しいコンテンツを貢献する場合でも、これらの原則は以下の理解に役立ちます。

* 優先するコンテンツの種類

* 新しい貢献の評価方法

* 特定のアプローチが他より推奨される理由

## 設計原則 {#design-principles}

### 実際のユースケースへの注力 {#focus-on-real-world-use-cases}

理論的な可能性よりも実践的なシナリオを優先します。コンテンツは、AWS ネットワーキングの専門家が日常的に直面する一般的な課題に対応する必要があります。

**例:**

* シングルアカウントのデモよりもマルチアカウントの接続パターン

* 基本的なセットアップよりも本番環境に対応したセキュリティ設定

* 実際の使用パターンに基づいたコスト最適化戦略

### 強固な基礎の優先 {#prioritize-strong-fundamentals}

信頼性の高いアーキテクチャの基盤となる、実証済みのネットワーキング概念を重視します。

**これが意味すること:**

* 基礎を理解することで、高度な設計や機能を評価するための土台が得られる

* 設計原則を把握することで、多様なユースケースにわたって情報に基づいた意思決定が可能になる

* トラブルシューティングの方法論を学ぶことで、技術的な実装を補完する診断スキルが身につく

### コア要素としての IPv6 {#ipv6-as-a-core-element}

IPv6 はオプションでも将来的な話でもなく、現代の AWS ネットワーキングに不可欠な要素です。

**私たちのアプローチ:**

* すべての例に IPv4 と IPv6 の両方の設定を含める

* 図はデフォルトでデュアルスタック実装を示す

* IPv6 の採用をオプションではなく必然として扱うガイダンス

### 技術的な精度と明確さ {#technical-precision-and-clarity}

正確で実践的な情報を必要とする経験豊富な実務者向けに執筆します。

**基準:**

* AWS ネットワーキングスペシャリストによる技術的正確性の検証

* 過度な単純化を避けた明確な説明

* コンテンツを重複させるのではなく、権威ある情報源へのリンクを提供
