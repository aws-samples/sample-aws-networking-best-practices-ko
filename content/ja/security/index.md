# セキュリティ {#security}

このセクションでは、グローバルエッジから個々のリソースまで、インバウンドトラフィックからアウトバウンド接続まで、そしてネットワークレベルの分離からアイデンティティベースのアクセス制御まで、AWS ネットワークをあらゆる層で保護する方法を説明します。AWS におけるネットワークセキュリティは、境界に設置された単一のファイアウォールではありません。各層が他の層で見逃したものを補完する、多重に重なり合ったコントロールの集合体です。

ここで取り上げるセキュリティコントロールは、接続性とアプリケーションネットワーキング層の上位で機能します。VPC 構造、サブネット階層、および接続パターンの設計が既に完了していることを前提としています。セキュリティは完成したアーキテクチャに後から付け加えるものではなく、最初からアーキテクチャを形成するものです。サブネット設計(専用ファイアウォール層)、ルートテーブルの設定(検査を通じたトラフィック誘導)、アカウント構造(最も強力な境界としての分離)に影響を与えます。

## 1. 境界コントロール {#1-perimeter-controls}

**境界コントロール**は、不正なインバウンドアクセスからネットワーク境界を保護します。AWS における境界は単一のファイアウォールではなく、グローバルエッジネットワークから個々の ENI まで、スタックの異なるレベルで動作する多層コントロールです。

**主要サービス:**

*   **Security Groups** — ステートフルな ENI 単位のアクセス制御。すべてのワークロードにおける主要なメカニズム
*   **Network ACLs** — 多層防御のためのステートレスなサブネットレベルの拒否ルール
*   **AWS WAF** — CloudFront、ALB、および API Gateway における L7 リクエスト検査
*   **AWS Shield** — DDoS 保護(Standard は自動適用、Advanced は上位ティア向け)
*   **AWS Network Firewall** — VPC 境界でのマネージドなステートフル/ステートレス検査
*   **Gateway Load Balancer** — サードパーティ製ファイアウォールアプライアンスの透過的な挿入
*   **AWS Firewall Manager** — 全アカウントにわたる一元的なポリシー管理

***重要なポイント:*** *Security Groups が主要なアクセス制御です。NACL でも Network Firewall でもありません。Security Group の設計を適切に行えば、他の層は補完的なコントロールではなく安全網として機能します。*

## 2. アウトバウンドコントロール {#2-outbound-controls}

**アウトバウンドコントロール**は、ワークロードがインターネット上のどこにアクセスできるか、またそのトラフィックが環境外に出る前にどのようにフィルタリングされるかを決定します。基本原則はアウトバウンドのデフォルト拒否、例外による許可です。

**主要サービス:**

*   **Security Groups(アウトバウンドルール)** — ENI レベルでのポートおよびプロトコル制限
*   **Route 53 DNS Firewall** — DNS 解決層でのドメインベースフィルタリング。最も安価で高速なエグレスコントロール
*   **AWS Network Firewall(エグレスルール)** — ステートフル検査、IPS シグネチャ、および SNI ベースのドメインフィルタリング
*   **VPC Endpoints** — AWS サービストラフィック(S3、DynamoDB など)のエグレスを完全に排除
*   **AWS Network Firewall Proxy(プレビュー)** — アウトバウンド Web トラフィック向けのマネージド明示的フォワードプロキシ

***重要なポイント:*** *DNS Firewall はすべての VPC に最初にデプロイすべきエグレスコントロールです。最も広い脅威対象領域を最低コストでカバーし、エグレスが集中型か分散型かに関わらず機能します。*

## 3. ネットワークセグメンテーション {#3-network-segmentation}

**ネットワークセグメンテーション**は、ネットワークを複数の層で分離されたセグメントに分割することで、影響範囲を限定します。AWS は、アカウントレベルの分離(最も強力な境界)からリクエスト単位のアイデンティティベースのアクセス制御(最も細粒度)まで、セグメンテーションを提供します。

**主要なメカニズム:**

*   **AWS アカウント** — 最も強力な分離: IAM、ネットワーク、および請求の境界を分離
*   **VPC** — 暗黙的なクロス VPC ルーティングのないネットワークレベルの分離
*   **Cloud WAN セグメント / Transit Gateway ルートテーブル** — ポリシー駆動のルーティングドメインセグメンテーション
*   **Security Groups** — 参照ベースのルールによるマイクロセグメンテーション
*   **VPC Lattice 認証ポリシー** — ネットワーク位置に依存しないアイデンティティベースのセグメンテーション
*   **サービス挿入** — Cloud WAN または Transit Gateway ルーティングを介したセグメント間の Network Firewall 検査

***重要なポイント:*** *最も安価なセグメンテーションが最も強力です。アカウントと VPC の分離はコストゼロです。まずは適切なアカウント構造に投資し、セグメント間の接続が必要な場合にのみルーティング層のセグメンテーションを追加してください。*
